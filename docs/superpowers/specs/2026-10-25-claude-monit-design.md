# claude-monit — จอแจ้งสถานะ Claude Code บน ESP32 CYD

วันที่: 2026-10-25

## เจตนาและเหตุผล

ผู้ใช้เปิด Claude Code หลาย session พร้อมกันบน Mac (รวมถึงตอนใช้ agent-teams) แล้วหันไปทำอย่างอื่น ปัญหาคือไม่รู้ว่า session ไหน **หยุดรอให้กดอนุญาต** หรือ **ทำงานเสร็จแล้ว** จอนี้ทำหน้าที่ดึงสายตาผู้ใช้กลับมาใน 2 จังหวะนี้ และบอกให้รู้ว่าเป็น **session ไหน** ตัวจอใช้ตัวละคร Clawd (มาสคอต Claude Code) แบบ pixel art ที่ขยับได้ ให้รู้สึกเหมือนมีเพื่อนตัวเล็กๆ นั่งอยู่ข้างโต๊ะ

## เป้าหมาย

- เห็นได้ทันทีว่ามี session ไหนรออนุญาต (ด่วนที่สุด) และ session ไหนเสร็จแล้ว
- แต่ละ session มีตัวละครของตัวเองที่ทำท่าตามสถานะ
- ไฟ LED บนบอร์ดช่วยเรียกความสนใจ ตอนผู้ใช้ไม่ได้มองจอ
- บอร์ดวางไว้ที่ไหนก็ได้ ขอแค่เสียบที่ชาร์จ แล้วรับข้อมูลผ่าน WiFi

## สิ่งที่ไม่ทำ (non-goals)

- ไม่แสดงตัวเลขอย่างจำนวน token, ค่าใช้จ่าย หรือ rate limit
- ไม่รองรับหลายเครื่อง (ใช้กับ Mac เครื่องนี้เครื่องเดียว)
- ไม่กดอนุญาตหรือสั่งงาน Claude จากบอร์ด (บอร์ดใช้แจ้งเตือนอย่างเดียว)
- ไม่มีโปรแกรม (daemon) ที่ต้องรันค้างไว้บน Mac

## สิ่งที่จะถือว่าล้มเหลว (anti-goals)

- hook ทำให้ Claude Code ช้าลงหรือค้าง ตอนบอร์ดปิดหรือหลุด WiFi
- ไปแก้หรือลบ hook เดิมใน `~/.claude/settings.json` (ตอนนี้มี hook ของ pixel-agents, iTerm2 cc-status และ superset อยู่แล้ว ต้องเพิ่มต่อท้ายเท่านั้น)
- สถานะผิดจนไม่น่าเชื่อถือ เช่น ช่องขึ้นสีส้มค้างทั้งที่ไม่มีอะไรรออยู่แล้ว

## ฮาร์ดแวร์

- บอร์ด ESP32-2432S028R (CYD) ชิป ESP32-D0WD rev1.0 ตรวจพบที่ `/dev/cu.usbserial-2110` ตอนแฟลช
- จอ TFT ILI9341 ขนาด 320×240 และทัชสกรีน resistive XPT2046 (ใช้ SPI แยกจากจอ)
- ไฟ LED RGB บนบอร์ด (active-low: GPIO4 = R, GPIO16 = G, GPIO17 = B)
- หมายเหตุ: บอร์ด CYD มีหลายรุ่นย่อย บางรุ่นต้องใช้ไดรเวอร์จอ ILI9341_2 หรือต้องกลับสี ให้ทำ sketch ทดสอบจอก่อน

## สิ่งที่ผู้ใช้ตัดสินใจแล้ว

1. **จังหวะที่สำคัญ** มีสองจังหวะคือ "รออนุญาต" กับ "เสร็จแล้ว"
2. **หลาย session** ต้องบอกให้ได้ว่าเป็น session ไหน
3. **เลย์เอาต์ B** ใช้ Claude หนึ่งตัวต่อหนึ่ง session จอแบ่งเป็นช่อง แต่ละช่องมีตัวละครกับชื่อ session
4. **ไฟ LED กะพริบ** ด้วย
5. **เชื่อมต่อด้วย WiFi** บอร์ดเสียบแค่ที่ชาร์จ
6. **ใช้กับ Mac เครื่องนี้เครื่องเดียว**
7. **ตัวละครแบบ A** ใช้ Clawd แบบ pixel art สไตล์ 8-bit สีส้มอิฐ `#db4900` บนพื้นหลังเข้ม (เดิม `#d97757` แต่บนจอจริงออกโอรส ผู้ใช้ขอเปลี่ยน)
8. ผู้ใช้ยืนยันพฤติกรรมของหน้าจอตามข้อ "หน้าจอ" ด้านล่าง (รวมถึงการแตะเพื่อรับทราบ)

## หน้าจอ

สถานะของแต่ละช่องมีดังนี้

| สถานะ | สีช่อง/ข้อความ | ท่าทางตัวละคร |
|---|---|---|
| รออนุญาต (waiting) | พื้นช่องส้มเข้ม ข้อความส้มกะพริบ | โบกมือเรียก ตัวเด้ง |
| เสร็จแล้ว (done) | ข้อความเขียว มี ✓ | กระโดดดีใจ ยกแขนสองข้าง ตายิ้ม |
| กำลังทำงาน (working) | ข้อความฟ้า | ขยับเร็วเบาๆ เหมือนกำลังพิมพ์ |
| ว่าง (idle) | จางลง | ตัวยุบ ตาหลับ มี z ลอยขึ้น |

- ใต้ตัวละครแสดงชื่อ session (ชื่อโฟลเดอร์ `cwd`) ตามด้วยสถานะ
- จำนวนช่องปรับตามจำนวน session: 1 = เต็มจอ, 2 = แบ่งครึ่ง, 3–4 = ตาราง 2×2, 5–6 = ตาราง 3×2 ถ้ามีมากกว่า 6 จะเลือกโชว์ตามลำดับ waiting > done > working > idle แล้วตามเวลาที่อัปเดตล่าสุด
- **แตะช่องที่ done หรือ waiting** แล้วช่องจะกลับเป็น idle (รับทราบ/เคลียร์เอง) ส่วนการแตะช่องสถานะอื่นไม่มีผล
- ช่อง waiting จะกลับเป็นปกติเองเมื่อผู้ใช้กดอนุญาตหรือปฏิเสธใน Claude Code (บอร์ดรู้จาก hook ถัดไป)
- session จะถูกลบออกจากจอเมื่อจบไปแล้ว (`SessionEnd`) หรือเมื่อไม่มี event เข้ามานานเกินกำหนด *(ระยะเวลาเป็นการตัดสินใจของผู้เขียน)*:
  - **working / idle:** ลบเมื่อเงียบเกิน 30 นาที
  - **waiting / done:** **ไม่ลบเพราะเงียบ 30 นาที** เพราะ session ที่รออยู่จะไม่ส่ง event อะไรมาอีก และนี่คือการแจ้งเตือนที่ห้ามพลาด จะลบเมื่อเงียบเกิน 8 ชั่วโมงเท่านั้น (กันช่องค้างข้ามวัน)
- ข้อจำกัดที่ยอมรับได้: ถ้าผู้ใช้กด Esc ที่หน้าขออนุญาต Claude Code อาจไม่ยิง event ใดเลย ช่องจะยังเป็นส้มจนกว่าจะเกิด event ถัดไปของ session นั้น เช่นพิมพ์ prompt ใหม่ ผู้ใช้แตะช่อง waiting เพื่อเคลียร์เป็น idle เองได้ *(การตัดสินใจของผู้เขียน)*. ให้ hook ส่ง `PreToolUse` มาด้วย ถ้าช่วยให้เคลียร์ waiting ได้เร็วขึ้นในบางกรณี
- ตอนยังไม่มี session ใดเลย ให้แสดง Clawd ตัวเดียวนั่งหลับกลางจอ พร้อมข้อความเล็กๆ แสดงชื่อ `claude-monit.local` และ IP
- mockup อ้างอิงอยู่ที่ `.superpowers/brainstorm/*/content/layout.html` และ `character.html`

## ไฟ LED (การตัดสินใจของผู้เขียน)

- มี session waiting อย่างน้อยหนึ่งตัว: ไฟส้มกะพริบ (ประมาณ 2 Hz) ไปเรื่อยๆ จนกว่าจะไม่มี session ไหน waiting
- มี done (และไม่มี waiting): ไฟเขียวกะพริบ 3 ครั้ง แล้วติดค้างไว้เบาๆ จนกว่า done ทุกตัวจะถูกรับทราบหรือเปลี่ยนสถานะ
- กรณีอื่น: ไฟดับ

## การเชื่อมต่อและข้อมูล

```
Claude Code (หลาย session)
  └─ hook command (สคริปต์เดียว) ──HTTP POST, timeout สั้น──▶ ESP32 (claude-monit.local)
                                                             └─ เก็บสถานะทุก session ไว้ในหน่วยความจำ
```

- **บอร์ดเป็นตัวแสดงผล** ไม่มี daemon บน Mac
- **กู้คืนสถานะ** *(การตัดสินใจของผู้เขียน)*: สคริปต์ hook เก็บไฟล์สถานะเล็กๆ ไว้ใน `~/.claude-monit/sessions/` หนึ่งไฟล์ต่อ session ทุกครั้งที่ hook ทำงาน มันจะอัปเดตไฟล์ของตัวเอง แล้วส่ง **สถานะปัจจุบันของทุก session** ไปให้บอร์ดแบบ snapshot ผลคือถ้าบอร์ดรีบูต, ไฟดับ หรือหลุด WiFi สั้นๆ จนพลาด POST ไป จอจะกลับมาถูกต้องเองเมื่อ session ใดก็ได้ส่ง event ถัดไป ดังนั้นการแปลง event เป็นสถานะ, การตั้งชื่อ `#2`/`#3` และการลบตาม timeout จะทำฝั่ง Mac ส่วนบอร์ดรับ snapshot มาแสดง และจับเวลาการลบซ้ำเองด้วย (เผื่อ Mac sleep)
  - การแตะ "รับทราบ" บนบอร์ดเป็นสถานะที่เกิดบนบอร์ดเท่านั้น บอร์ดจะจำ `session_id` + เวลาที่รับทราบไว้ และไม่ให้ snapshot เก่าที่ส่งมาทีหลังทับกลับเป็น done/waiting เว้นแต่ไฟล์สถานะของ session นั้นมี event ที่ใหม่กว่า (ต้องส่ง timestamp ของ event ล่าสุดมาใน snapshot ด้วย)
  - ไฟล์สถานะเก่ากว่า 8 ชั่วโมงหรือของ session ที่ `SessionEnd` แล้ว ให้ลบทิ้งตอน hook ทำงาน
- บอร์ดประกาศชื่อผ่าน mDNS ว่า `claude-monit.local` และเปิด HTTP server
- **เผื่อ mDNS ใช้ไม่ได้** *(การตัดสินใจของผู้เขียน)*: hook อ่านที่อยู่บอร์ดจาก env `CLAUDE_MONIT_HOST` หรือไฟล์ `~/.claude-monit/config` ก่อน ถ้าไม่มีจึงใช้ `claude-monit.local` และควร cache IP ที่ resolve ได้ไว้ด้วย เพราะการ resolve `.local` บน macOS อาจช้า บอร์ดแสดง IP บนจอตอนบูตและตอนไม่มี session ผู้ใช้จะได้ใส่ IP เองได้ถ้าจำเป็น
- **ตั้งค่า WiFi:** ตอนเปิดเครื่องครั้งแรก หรือต่อ WiFi ที่บันทึกไว้ไม่ได้ บอร์ดจะเปิด AP ชื่อ `claude-monit-setup` พร้อม captive portal ให้เลือก SSID และใส่รหัสผ่าน (ใช้ไลบรารี WiFiManager) ระหว่างนั้นจอแสดงวิธีต่อ
- ถ้าต่อ WiFi ไม่ติด ให้ขึ้นข้อความบนจอ ห้ามจอค้าง

### สคริปต์ hook ฝั่ง Mac

- สคริปต์ตัวเดียว (เช่น `hooks/claude-monit-hook.sh` หรือ `.js`) รับ JSON ทาง stdin ตามรูปแบบ hook ของ Claude Code (`session_id`, `cwd`, `hook_event_name` และอื่นๆ) แล้ว POST ข้อมูลที่ย่อแล้วไปที่บอร์ด
- ต้องจบเร็วเสมอ: ตั้ง connect timeout ประมาณ 0.5 วินาที, ส่งแบบไม่รอ (background หรือ fire-and-forget), exit 0 ทุกกรณี และห้ามพิมพ์อะไรลง stdout เพราะบาง hook นำ stdout ไปใช้
- ติดตั้งแบบ **global** ใน `~/.claude/settings.json` โดย **เพิ่ม** entry ใหม่ ห้ามแก้ entry เดิม และให้มีสคริปต์ install/uninstall ที่ทำงานซ้ำได้โดยไม่ซ้อนกัน

### การแปลง hook เป็นสถานะ

| Hook event | สถานะ |
|---|---|
| `SessionStart` | idle (สร้างช่องใหม่) |
| `UserPromptSubmit` | working |
| `PermissionRequest` หรือ `Notification` ที่เป็นการขออนุญาต | waiting |
| `PostToolUse` / `PostToolUseFailure` | working (เคลียร์ waiting หลังผู้ใช้กดอนุญาตแล้ว) |
| `Stop` | done |
| `SessionEnd` | ลบช่อง |

- ข้อจำกัดที่รู้อยู่แล้ว: หลังกดอนุญาต ถ้า tool นั้นรันนาน (เช่น bash ที่ใช้เวลาหลายนาที) ช่องจะยังเป็น waiting จนกว่า tool จะรันเสร็จ ผู้เขียนยอมรับข้อจำกัดนี้ได้ แต่ถ้า builder หา event ที่บอกว่ากดอนุญาตแล้วได้ ให้ใช้ event นั้นแทน
- ผู้ใช้กดปฏิเสธ: Claude จะทำต่อหรือหยุด ซึ่งจะได้ event ถัดไป (`UserPromptSubmit` หรือ `Stop`) มาเคลียร์สถานะเอง
- Subagent (`SubagentStop`) ไม่นับเป็น session แยก

### ชื่อ session

- ใช้ชื่อโฟลเดอร์สุดท้ายของ `cwd` และระบุตัวจริงด้วย `session_id`
- ถ้าหลาย session อยู่โฟลเดอร์เดียวกัน (เช่น agent-teams ที่ lead กับ specialist อยู่ใน repo เดียว) ให้ต่อท้ายด้วย `#2`, `#3` ตามลำดับที่เข้ามา *(การตัดสินใจของผู้เขียน)*
- ถ้าชื่อยาวเกินช่อง ให้ตัดแล้วใส่ `…`

### API ของบอร์ด (ส่วนที่ builder ออกแบบเองได้)

- ต้องมี endpoint ที่รับ snapshot ของทุก session: `[{session_id, name, state, updated_at}]` (การแปลง event อยู่ฝั่ง Mac ตามหัวข้อ "กู้คืนสถานะ")
- ควรมี `GET /` หรือ `/status` คืนสถานะทั้งหมดเป็น JSON ไว้ debug

## เครื่องมือที่ใช้ (การตัดสินใจของผู้เขียน)

- เฟิร์มแวร์ใช้ **PlatformIO + Arduino framework** วาดจอด้วย **TFT_eSPI** (ตั้งค่าผ่าน build_flags ใน `platformio.ini`) อ่านทัชด้วย **XPT2046_Touchscreen** และตั้งค่า WiFi ด้วย **WiFiManager**
- ตัวละครเป็น pixel art แบบ bitmap/primitive วาดเอง ไม่ใช้ asset ที่มีลิขสิทธิ์ ใช้ sprite (off-screen buffer) เพื่อไม่ให้จอกะพริบ
- **ใช้ตารางพิกเซลจาก mockup** `character.html` (16×14 พิกเซลต่อเฟรม ท่าละ 2 เฟรม) ตามที่ผู้ใช้เลือก แล้วขยายแบบจำนวนเต็มตามขนาดช่อง (เช่น เต็มจอ ×8, แบ่งครึ่ง ×5, 2×2 ×4, 3×2 ×3) builder ปรับเฟรมให้ลื่นขึ้นได้ แต่ต้องไม่เปลี่ยนหน้าตาตัวละคร
- ต้องติดตั้ง PlatformIO (`pip install platformio` หรือ brew) ในเครื่องก่อน ตอนนี้ยังไม่มี

- ทดสอบจริงบนบอร์ด: เปิด 2–3 session แล้วไล่ให้เกิดครบทุกสถานะ
